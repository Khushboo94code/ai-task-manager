# Task Deletion Policy

## When to Delete a Task
Tasks should only be deleted if they were created by mistake or are exact duplicates of an existing task. Deletion is a permanent action with no undo.

## When NOT to Delete
- Do not delete completed tasks. Mark them as completed and leave them for audit history.
- Do not delete a task just because it is no longer a priority. Mark it low priority or add a note in the description.
- Do not delete a task that is in_progress without first moving it back to pending and notifying the team.

## Confirmation Required
All delete operations require explicit user confirmation. The assistant will always ask you to confirm before deleting any task. This two-step process prevents accidental data loss. The confirmation expires after 5 minutes.

## Who Can Delete
Any team member can delete a task they created. Deleting another team member's task should be discussed with them first.

## Alternatives to Deletion
- Task no longer needed: mark it as completed with a note explaining why.
- Task is a duplicate: update the original with any new information, then delete the duplicate.
- Task is too large: break it into smaller subtasks rather than deleting.

## After Deletion
Deleted tasks are permanently removed from the system. There is no trash folder or recovery mechanism.
