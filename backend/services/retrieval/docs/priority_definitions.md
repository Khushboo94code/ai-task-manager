# Priority Definitions

Tasks have three priority levels: low, medium, and high.

## High Priority
High priority tasks (also called urgent, critical, or top priority) block other work or have a deadline within 48 hours. These must be worked on immediately and take precedence over all other tasks. Examples: production bugs, security issues, blocked teammates, broken deployments.

## Medium Priority
Medium priority tasks (also called normal or moderate) are important but not immediately blocking. They should be completed within the current sprint or week. Examples: feature development, planned improvements, non-critical bug fixes.

## Low Priority
Low priority tasks (also called minor or trivial) are nice-to-have or have no immediate deadline. They can be deferred if higher priority work comes up. Examples: documentation updates, minor refactoring, cosmetic UI tweaks.

## Rules
- Every task must have a priority. Default is medium if not specified.
- Urgency should be reassessed daily during standups.
- If a low priority task becomes blocking, immediately escalate it to high.
- Priority is set by the task creator and can be updated by any team member.
- Do not use the task title to express urgency (e.g., "URGENT: fix bug") — set the priority field instead.
