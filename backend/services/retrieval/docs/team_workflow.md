# Team Workflow and Task Management Guidelines

## Daily Standup
Every team member reviews their in_progress and overdue tasks before the daily standup. Tasks that have been in_progress for more than 3 days without progress should be discussed.

## Creating Tasks
Any team member can create a task. Before creating a task, search for existing tasks to avoid duplicates. Provide a clear title and a description with enough context for anyone on the team to pick it up.

## Assigning Work
Tasks are self-assigned. When you start working on a task, change its status to in_progress. Do not start a task if you already have more than 3 tasks in_progress — complete or hand off existing work first.

## Task Sizing
Tasks should be completable within 1 to 3 days. If a task takes longer, break it into smaller tasks. Large tasks (more than 5 days) are not allowed and should be decomposed.

## Communication
Use the task description to log important updates or blockers. If a task is blocked by another task or external dependency, note this clearly in the description and lower its priority until the blocker is resolved.

## Definition of Done
A task is considered done (completed) when:
1. The work described in the title and description is finished.
2. Any relevant tests pass.
3. The change is reviewed by at least one other team member if it affects shared code.
4. The task status is set to completed.
